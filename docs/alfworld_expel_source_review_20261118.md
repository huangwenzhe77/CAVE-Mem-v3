# ALFWorld 来源记忆工程试跑与项目对照（2026-11-18）

## 对照结论

- [ExpeL](https://github.com/LeapLabTHU/ExpeL) 保存同题多次尝试的成功和失败轨迹，再用它们生成反思/批评；ALFWorld 提示按六类任务给具体行动示例。其同题对照值得借鉴，但 ExpeL 的反思重试和文本经验并不等同于本项目要求的“一个失败轨迹一个修正候选、独立配对回放确认 `v`”。因此本试跑保留固定 actor，教师可读同题历史成功轨迹，修正是否入库仍由 K=2 决定。
- 先前的 [CAVE-Mem](https://github.com/huangwenzhe77/CAVE-Mem) v2 使用无效动作、无可见进展、重复动作来定位可检验的失败点；这些是线索，不是错误原因证明。其 README 明确报告的是 76 项离线测试，尚未执行真实 ALFWorld/模型服务实验。它的 ALFWorld 适配器没有认证完整恢复，因此采用单臂路径。v3 记录固定游戏及动作前缀，并逐点审核两个独立恢复实例；审核通过时必须用配对，不能为了凑单臂样本改写恢复能力。
- v3 此前长轨迹只展开边界和四分位检查点，教师易漏看中部停滞。现将 v2 的公开失败线索用于展开检查点，并向教师公开 ALFWorld 的 `task_type` 家族字段以帮助提出可迁移条件。线索不进入 `v` 判定，也不改变每条失败历史只留一个有效候选的规则。

## 解释边界

`v=1` 只证明来源检查点上该修正连续两次成功且平均效用差为正。它不证明教师文字机制的因果性，也不证明对其他场景有帮助。三条入库记忆里有一条使用了很具体的原题指令，另外两条使用“容器关闭/打开后为空”等较通用的观察条件；后者也可能过宽。必须在目标检查点核对 `ρ`、实际 Silent/Remind 结果和伤害标签 H。

当前固定的 ALFWorld TextWorld 游戏能够用动作前缀恢复；因此自动路由中的有效检查点预计主要是配对。任务提前完成而未抽中检查点属于预先定义的抽样排除，不应转写为单臂。只有真实恢复不被认证或审核失败时才进入单臂。

AIcodemirror 网关返回模型别名但未给可核验权重指纹，结果记录了此限制。15 步使历史失败与成功同时存在，却使部分修正缺少余量；两个第 15 步修正候选均未通过 K=2。后续若需调整预算或检查点窗口，应新建冻结试跑，不能改写这批证据或使用验证/测试任务调参。

## 目标数据

`alfworld-aicodemirror-sol-target-r08/` 使用上述来源库和 `target_train` 48 题，在线抽样概率为低风险 0.20、高风险 0.85，单臂提醒分配概率为 0.5。只读汇总为 24 个配对路线、5 个未抽中检查点、19 个准备错误；配对里 23 个有效、1 个因恢复执行错误阻断。有效配对原始结局含 1 个 H、1 个救援；但运行后段的 20 个非 agent 错误使它**不是**无故障的正式目标批次。错误原因是 TextWorld 在共享 `/tmp` 复制 `fast_downward.so` 时遇到 `ENOSPC`。导出数据时必须查看真实 `by_route`；旧 `by_kind` 把 `none` 排除行放在单臂形状里，并不表示有单臂执行。

新的 `alfworld-aicodemirror-sol-target-r09/` 保留同一完整来源库、actor 和 15 步预算，抽样概率固定为低风险 0.35、高风险 0.90。运行时使用本机 ext4 的私有 `/var/tmp/cave-alfworld-ljj-r09`，并让编码器使用 NumPy 1.26.4。启动前已实际执行一次 ALFWorld reset 与 384 维编码；网络文件系统上的临时目录经测试会在动态库清理时触发 `.nfs` 残留，不能使用。

r09 已完整闭合：48 题中 43 个有效配对、5 个未抽中检查点，准备、恢复与模型接口错误均为 0。有效配对中 Silent/Remind 都失败 17、仅 Remind 成功 4、仅 Silent 成功 3、都成功 19；`H=1` 有 3 条，救援 4 条。导出的目标训练视图有 43 条有效配对结果、D、H 和救援标签，5 条未抽中排除，真实单臂为 0。配对事后 e 教师标注 43/43 可解析，其中 e=0 为 37、e=1 为 1、`?` 为 5；教师判断不能视为物理机制的因果证明。

这批目标数据仍有明显覆盖限制：43 个配对中，42 个检索到同一条来源记忆，只有 9 个的 `ρ=1`；即使 H 不全为 0，也不足以宣称记忆匹配和后续策略训练已达到预期。e 与 H 也不是同一标签：3 个 H=1 的配对均被教师标为 e=0，这说明提醒可能在历史机制未触发时造成伤害，或教师判断有误；须保留两者的独立含义。

离线训练烟测使用显式 `gamma=1`。默认 4000 次迭代、`tolerance=1e-6` 时，D 的 `tau` 头已拟合，但 H 的无正则逻辑回归头未收敛；这不是 H 全 0（标签为 40 个 0、3 个 1）。另一次保持 Eq. 7 目标函数不变，仅设 `max_iterations=25000`、`tolerance=1e-3` 的试跑在第 17080 次让 H 头达到数值收敛。该模型仅用于证明数据可进入训练代码，43 行加 384 维嵌入有严重过拟合风险。网关未返回费用，因此 `api_cost` 头不可用，其余观测到的成本头可拟合。

## 扩展来源与检索诊断

另行冻结的 `alfworld-manifest-expanded-clean.json` 含 48 history、48 target_train、12 validation、12 test；其 120 个场景与前述 96 个场景无交集。`alfworld-aicodemirror-sol-expanded15-history-r10/` 已采集 96/96 条有效历史轨迹，成功 48、任务失败 48，非 agent 错误为 0。每个失败轨迹最多保留一个候选。教师首次生成有 21 个合法候选，按保留原记录、只重试被拒项的规则最终达到 48/48；同题成功参考只在 8 条失败轨迹中可用。`alfworld-aicodemirror-sol-expanded15-verification-r10-v2/` 的 K=2 审核得到 11 条 `v=1` 入库、35 条 `v=0`、2 条 `v=?`；后两条的声明修正动作没有实际执行，不能计为验证通过。

`alfworld-aicodemirror-sol-expanded15-target-r12-gpt61actor/` 使用该来源库、48 个独立的 `target_train` 场景、15 步预算与 `gpt-6.1-sol` actor；来源 actor 是 `gpt-5.6-sol`，故它不是同 actor 的消融比较。48 题全部闭合：46 个有效配对、2 个未抽中检查点，准备/恢复/模型错误为 0；配对结局为两臂皆失败 11、仅 Remind 成功 10、仅 Silent 成功 5、两臂皆成功 20，`H=1` 为 5。该批次只检索到 3/11 条来源记忆，46/46 个 `ρ=0`，因此虽有非零训练标签，记忆匹配没有达到目标。

原因是旧检索将冗长房间清单与可选动作一并编码后直接取余弦 top-1，曾把加热任务选到冷却记忆。修正后的排序先比较公开的 ALFWorld `task_type` 与记忆的明确家族条件，再比较同家族记忆的公开条件适用性，最后以原余弦分数决胜；仍只选择一条记忆，`ρ` 本身按原规则计算，目标结局不参与排序。对 r12 已保存的 46 个公开检查点作**离线**重检，选中的不同记忆从 3 条增至 9 条，`ρ=1` 从 0 增至 13；13 正是这些检查点中至少有一条已入库记忆满足条件的数量。仍有 33 个 `ρ=0`，需要更多适用的来源记忆，而不是强改标签。

真实重跑尚未完成：r13 在第 2 题遇到一次网关 120 秒推理超时，按不可静默重试的日志规则保留为未完成批次；r14 将接口等待设为 240 秒，后依用户要求手动停止，停止时 3/48 已闭合。两批原始记录均保留在 `/home/ljj/CAVE-Mem-v3/runs/`。因此新检索的配对效果、事后 `e`、以及可用于后续训练的完整新数据集尚无结论。该 TextWorld 设置的恢复审核持续通过，目标检查点应走配对；未抽中检查点是 `none`，不能充作单臂样本。
