## 执行约定

1. 用户点名卡号时只执行该卡；用户只说“继续”时，选下一张前置条件已满足的卡，先声明卡号和边界。一次只有一张 `in_progress` 卡。
2. 开始前检查 Git 状态、HEAD 和该卡前置产物。保留已有未提交改动；本项目当前未提交工作不能被 reset、clean 或顺手提交。
3. 卡片的路径是允许的主要改动范围，尚不存在的路径是拟新增路径。必要修复限定于该卡验收，不顺手重构或实现后续卡；若需要新的行为改动，记录另卡。
4. 每张卡继承下面的公共 Rules，同时遵循自身 Rules。不能通过减弱恢复、评分、信息隔离或成本规则达成 Acceptance。
5. 代码卡运行针对本卡的 focused checks，再运行 `python scripts/run_tests.py`；失败则继续修复本卡。纯文档卡核查定义、示例和链接，无需为文案写测试。
6. 结束交付：卡号/状态、每个新增或修改文件及作用、命令与实际结果、实验设置和产物、未解决限制。更新本卡状态与执行记录，**停止，不开始下一卡**。
7. 若卡要求真实运行，必须已有可审查的冻结配置与协议；不符合已审核 Terminal 文件系统协议时，先提交具体 adapter/协议变更供审阅，未解决前停止依赖它的运行。已完成的授权不重复询问。

公共 Rules：

- 不读取 test 结局来生成记忆、选参数或开发；保持任务/模板/依赖分组隔离。
- 不把教师假说当 `v=1`；不用来源修正证据代替目标提醒效果。
- 小写 `e_t` 是动作暴露，大写 `E` 是来源证据；`ρ/e` 未知不补造，不按 `ρ=e=1` 筛主样本。
- 固定 actor、teacher、encoder、提示、资产、种子和预算；不下载权重、不调用外部模型，除非所选卡的明确范围需要且运行条件已满足。
- 不把密钥、本地配置、权重、`runs/` 加入 Git；失败/未完成产物保留，不覆盖、不静默重试。
- fixture 只证明软件行为；真实实验结果单列。没有正结果仍可以如实完成运行卡。
- 本轮决定的新来源规则为 K=2、两组修正均成功且平均效用差严格超 epsilon；旧证据按旧版本审计，不自动改标。
- 不因完成一张卡自动开始另一张；不因列出了后续阶段就实现它。
