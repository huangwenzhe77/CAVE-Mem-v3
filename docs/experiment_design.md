# CAVE-Mem-v3 实验设计草案

状态：方案讨论稿（2026-11-13）。第一部分正在独立实现；本文件定义实验顺序和证据标准，不代表真实实验已经运行。以 proposal 为准，唯一已确认的公式勘误是 Eq.2 中的 `E` 应为小写 `e_t`；Eq.1 记忆元组中的大写 `E` 仍为来源证据。

## 0. 研究问题与边界

核心问题：对于已经由历史失败验证、且可在当前任务中检索到的记忆，看到执行模型原本要做的动作之后，何时提醒能提高终局效用，何时会增加失败风险或计算成本？固定任务执行模型、提示词、工具权限、检索器和编码器，只训练 Silent/Remind 控制器。主要研究单位是一次目标任务中的一个预先选定检查点；多检查点连续决策留待后续研究。

四部分依次产出：**来源证据与冻结记忆库 → 检查点随机实验数据 → 收益/风险模型与决策策略 → 冻结部署和未见任务评估**。源码修正回放、目标文字提醒、学习策略的证据分别建立，不能用前一步成功代替后一步结论。

### 必须先统一的变量

| 符号 | 操作定义 | 数据边界 |
| --- | --- | --- |
| `m` | 来源轨迹、原错误动作、候选修正、失败机制假说、正反适用条件、独立回放证据、证据范围 | 来源任务生成，冻结后才进入目标实验 |
| `a0` | 执行模型在完全未见记忆时产生并缓存的下一动作 | 提醒前只采样一次；Silent 直接执行 |
| `v` | 来源证据是否支持修正，取 `1/0/?` | `v=1` 只表明来源范围内的证据通过，不能表示目标有效 |
| `ρ` | 当前公开状态是否满足失败机制的环境前提，取 `1/0/?` | 不读取隐藏状态或未来结果 |
| `e` | 按 proposal §2.1/§3.2，`e_t=X(m,h_t,a0)` 估计当前原动作是否激活历史失败机制，取 `1/0/?` | 暴露及置信度与适用性分别记录，不以相似度替代 |
| `x` | 更正后的 `x_t=F_ω(c_t,a0_t,m,e_t,d_t,v_t,ρ_t,b_t)` | 全部在随机分配前冻结；`E` 仍存在于记忆 `m` 中 |
| `R` | 终局成功减去预登记的模型与工具成本惩罚 | 成功率和绝对 token/耗时/工具次数另报 |

保持 proposal 对 `e` 的原定义。自然任务里 `ρ/e` 不可判定时保留 `?`，不靠相似度或事后成功标签补值。四格测试的可实现性与判定规则属于第二部分需要核验的操作细节，第一部分不擅自重定义 `e` 或实现相关控制器。

## 1. 构建历史失败记忆

**1.1 固定来源协议。** 先选定来源任务、冻结 actor 的具体权重/版本、提示词、温度、工具规则、最大步数、评分器、成本口径和恢复协议。记录原始成功/失败轨迹、公开观察、原动作和检查点快照。来源与目标任务的依赖关系在观察目标结果之前登记。

**1.2 提出可证伪修正。** 从失败轨迹定位少数候选步骤，结合成功轨迹或人工审查提出失败机制 `f`、替代动作 `ã`、正反适用条件、危险动作模式和失效边界。解释文本是机制假说；候选动作必须合法、可执行。不得把目标测试任务的答案、私有评分器结果或未来结果写进记忆与特征。

**1.3 来源回放。** 在同一来源检查点分别执行原动作与修正动作，之后使用同一冻结 actor 和预算继续。先用筛选样本确定候选，再用独立确认样本估计来源增量效用及置信区间；失败恢复、调用异常、超时单独记录。只有预登记终点的改善达到证据门槛才标为 `v=1`。预登记筛选数量、确认样本与停止规则；v2 配置的 4 对筛选/32 对确认仅是工程 pilot 参数，不能默认提供足够精度。

**1.4 冻结记忆库。** 每条记忆保留来源任务/轨迹/检查点 ID、原与修正动作、机制与适用条件、独立证据、验证范围、证据质量和内容哈希。未验证或相互矛盾记忆单列为噪声鲁棒性材料，不进入主实验候选库。检索固定为 top-1，记录无候选及检索失败，禁止依据目标结局回写主实验记忆。

**本部分放行条件：** 至少有来自多个独立来源的已确认记忆；回放恢复与私有评分隔离经审计；记忆条件和动作模式可由目标的公开观察判定；来源证据的置信区间与适用范围已记录。若没有足够来源，先扩来源任务，不启动策略训练。

## 2. 收集目标任务的提醒实验数据

**2.1 两条互补实验线。** 自然任务线先回答“正确且适用的提醒是否也会干扰安全原动作”；控制线用可恢复的 `ρ×e` 四格任务分别覆盖 `(0,0)、(0,1)、(1,0)、(1,1)`，重点检验 `(1,0)` 的无谓提醒/回退与 `(1,1)` 的救援。控制线用于机制辨识，自然任务线用于外部有效性。预先改变任务或公开环境条件，以提高各格的出现率；仍须让冻结 actor 自然生成 `a0`，再按实际 `ρ/e` 分层并报告预期格与实际格不一致率。脚本指定动作只能用于单列的机制单元测试，不能作为真实 actor 主效果证据。加入无效或矛盾记忆库作为另一个预登记鲁棒性条件。

**2.2 抽样与处理。** 在看到终局结果前，根据预登记规则从每个目标任务选择至多一个主检查点，并记录纳入概率、未入选和无候选情况。先缓存 `a0`、检索候选、冻结 `x`，然后随机化。Silent 执行 `a0`；Remind 给一次短、可追溯来源的提醒，允许 actor 重新提出一次动作。此后两臂使用同一 actor、工具规则和续跑预算；提醒不持续注入。配对执行时随机化两臂运行顺序，记录共同草稿开销和提醒的额外调用。

**2.3 两类数据不混称。** 只有环境恢复被认证、两臂从等价检查点和明确随机耦合续跑时，才记录配对 `D=R(1)-R(0)`、救援 `1{Y0=0,Y1=1}` 和回退 `H=1{Y0=1,Y1=0}`。模型服务不保证完全相同随机流时，报告该耦合的局限。不可配对环境按已知且非零的 `b(z|x)` 随机收集单臂结果，只估计边际策略价值；不能由单臂数据构造 `H`。两臂执行或基础设施错误不得静默当作任务失败。

**2.4 可审计记录。** 每条记录包含任务/模板/机制/来源依赖 ID、选择概率、检查点及公开特征版本、记忆与 actor 哈希、`a0`、`v/ρ/e` 及未知原因、随机种子/倾向概率、两臂或单臂终局、模型 token、工具调用、耗时、失败状态和排除原因。标注 `ρ/e` 的规则或人工审核者应对目标结局盲化。训练时可分层加采稀有 `(1,0)`，正式汇总按自然分布和已知抽样概率加权。

**本部分放行条件：** 恢复认证明确；自然样本及四格覆盖有足够独立任务/模板；`ρ/e` 的标注一致性和 `?` 比例可接受；随机化日志和处理顺序可核查；来源、目标任务、模板和机制的分组划分在终局数据采集前冻结。样本量由先导实验的组间方差、目标最小效应和回退事件发生率计算，重复复本不能充当独立任务。

## 3. 训练与选择策略

**3.1 数据分工。** 顶层分为历史任务、目标训练任务、验证集和测试集。历史任务只用于第一部分来源记忆；目标训练任务用于第二部分干预采集及第三部分学习；验证集内部区分校准与策略选择；测试集只用于最终冻结评估。先按目标任务/模板家族及复本依赖分组，再登记来源/机制留出轴；共享来源库的探索实验只能声称该固定库条件下的目标泛化，不能当成 proposal 所需的跨来源/机制留出。正式留出需要按来源 lineage、机制与目标依赖另建互不交叉的记忆库及实验清单。训练集内交叉拟合用于单臂 DR，验证不接触最终测试；额外审计子集是可选工程安排，不作为 proposal 新要求。

**3.2 从简单模型到复杂模型。** 在配对训练集拟合条件收益 `τ(x)`、配对回退风险 `h(x)` 与增量成本，独立校准及报告分组不确定性。先测试同容量监督阈值策略，再测试直接用配对 `D` 优化的二动作策略；只有单臂随机日志时才使用倾向概率、交叉拟合的 `μ0/μ1` 和 DR 评价/优化，并报告权重分布、有效样本量、截断敏感性。不能把 DR 当成配对标签来源。

**3.3 约束与基线。** 确认性主实验的回退预算 `δ`、额外计算预算 `B`、奖励权重、成功指标与选型规则须在阶段二目标结局采集前预登记。探索 pilot 可以调整这些量，但调整后须在新的未触碰样本上确认。策略在来源无效或预计净收益证据不足时退回 Silent。比较无记忆、总提醒、相关性阈值、仅来源证据、仅适用性、仅动作模式、`v=ρ=e=1`、同容量监督门控、无风险约束策略、完整约束策略。组件对照共享同一候选库、actor、评分和预算。ExpeL、MemRL 等完整原系统另外在兼容任务上运行并明确协议差异；不能把改写的局部规则命名为原系统复现。proposal 还要求与主动提醒及局部动作验证强基线比较，正式主结论前须完成或明确无法对齐的范围。

**本部分放行条件：** 收益与风险校准、有效样本量和分组外验证可信；策略在独立选择集的实际 rollout 中优于简单规则/监督门控，且经验回退与成本上界满足预登记预算。若简单门控同等有效，应保留简单方法并修订“RL 提供额外收益”的主张。

## 4. 部署与最终评估

在最终测试前锁定 actor、主记忆库、特征规则、策略权重、阈值、任务集合、检查点选择规则和所有预算。按任务随机分配冻结策略或基线，运行完整任务，包括未遇到检查点、没有合格记忆和策略保持 Silent 的任务；报告 end-to-end pass@1、净效用、提醒频率、无谓提醒、绝对 token/工具/耗时、覆盖率与失败原因。可信配对测试另报救援和回退；单臂部署只报告边际差异。按独立任务/模板/来源连通组做置信区间，列出权重和纳入概率，不能把同一检查点的复本当作独立样本。

按四格、来源有效性、任务/机制留出、噪声库和第二档冻结 actor 分层报告。显著改善终局结果且满足成本/回退预算，才支持主结论；否则报告负结果和可解释的适用范围。**Inspect** 是独立后续扩展：只在二动作策略有可信收益后，预登记只读诊断、探针成本，再收集第一阶段三动作和 Inspect 后第二阶段随机化数据；二动作日志不能识别 Inspect 的信息价值。

## 近期执行顺序与依赖

1. 先用 v2 的六任务 Terminal-Bench 文件系统 pilot 清单做工程可行性审计：容器恢复、actor/API、来源回放、公开事实与 `ρ/e` 规则。它只有一个来源任务，不能用于正式五集合训练，也不能称为官方 Terminal-Bench 排行榜结果。
2. 扩充并冻结来源/目标任务与独立分组；完成第一部分来源记忆的筛选、独立确认和记忆库冻结。这是下一次实现讨论的唯一优先部分。
3. 预登记自然现象 pilot、四格任务与样本量计算，完成第二部分；只有数据通过放行条件才启动第三部分训练。
4. 完成冻结策略的独立任务评估，再决定是否投入 Inspect 与跨检查点策略。

## 与现有仓库的关系

- `CAVE-Mem-v2` 已有来源回放、公开特征、配对/单臂采集、数据划分、策略学习和评估接口，可作为工程参考；其 README 截至 2026-11-12 只报告 76 项离线测试，尚无真实 Docker/API/官方任务实证。v3 不继承这些测试作为论文证据。
- `ExpeL` 提供经验提炼、反思与示例检索的完整系统参考；本地副本还混有 CAVE-Mem 相关扩展，复现原系统时须固定上游版本与配置。
- `MemRL` 提供两阶段检索、记忆效用更新和多 benchmark runner 的参考；其记忆 Q 值不等于本项目的动作条件提醒增量效用 `τ(x)`。
- proposal-2.pdf 的 §2–5 与用户四张流程图是本草案的研究依据。按用户 2026-11-13 更正，Eq.2 使用小写 `e`，保留原文对暴露的定义。Inspect 依 proposal 作为主二元实验之后的独立扩展。
